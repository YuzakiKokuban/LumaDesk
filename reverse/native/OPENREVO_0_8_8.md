# OpenRevo 0.8.8 功能与协议分析

分析日期：2026-10-06。样本由用户提供，文件名为 `open-revo-v0.8.8-6a67b94.7z`。本轮只解析文件，没有运行样本、安装驱动或写入硬件。结论与当前机耀处源码交叉核对；不代表完成实机适配，也没有旧版对应二进制可证明哪些功能首次出现在 0.8.8。

## 建议优先级

| 优先级 | 值得借鉴的功能 | 当前机耀处的差距 | 实现边界 |
| --- | --- | --- | --- |
| 1 | 离电自动降低内屏刷新率，插电恢复 | 已有显示器枚举、刷新率切换与供电事件；旧兼容命令仅保存配置并立即切最低刷新率，未形成供电变化规则 | 识别内屏、保存原档位、尊重用户手动修改；补热插拔与睡眠恢复。插电恢复是我们的建议，本轮未确认原版完整恢复规则 |
| 1 | 背光空闲熄灭、输入后恢复 | 单色硬件控制已可用；待机熄灯 HAL 仍拒绝为未适配功能 | 记录实际背光状态，避免覆盖用户或固件新设置；独立计时不能重新启用隐藏窗口遥测 |
| 1 | 可命名、可复制的性能配置 | 已有预设数据与导入导出 API，但现有电源页主要开放三档 | 先组合已验证的档位、Windows 电源模式等；功耗、风扇和 MUX 按各自能力限制开放，不把保存配置视为硬件已应用 |
| 2 | CPU/GPU 风扇曲线、联动与渐变速度 | 强冷已实现；曲线、渐变与独立输出 HAL 仍拒绝 | 本轮恢复了表写入与提交链；尚需恢复曲线到硬件表的转换及退出策略，再做回读、温升和故障恢复验证 |
| 2 | GPU cTGP / Dynamic Boost 与频率偏移 | 现有 NVML 读取可用，GPU 功耗和频率写入未接入 | EC 功耗与 NVAPI 频率是两套接口；按实际能力、供电方式及固件限制区分，先读后写并提供恢复 |
| 3 | 每屏色彩配置、CPU 频率上限、睡眠策略 | 部分 API 或旧配置结构存在，但产品流程不完整 | 色彩需处理 HDR、显示器身份及恢复；锁频/睡眠需保存 Windows 原设置，本轮尚未完整恢复其策略 |
| 3 | Fn 锁设置、关机 USB、来电开机、动态灯效 | Fn 锁读回已验证，其余写入尚未接入 | 本轮确认界面/命令存在；没有把这些入口提升为完整可用协议 |
| 按需求 | BLE 外置水冷、插件小组件和皮肤 | 尚未接入相应设备协议或产品机制 | 当前目标机型和用户需求确认后再投入；BLE GATT、断连保护与执行权限需单独分析 |

建议先落地前两项日常功能，再完善配置；下一轮硬件逆向优先风扇曲线，其次 GPU 功耗。原有充电上限、MUX、单色背光、OSD、OEM 接管等已有对应能力，不需要为了功能数量重复实现。

## 风扇：已从入口追到原生写入

前端 `apply_fan_curve_live` 传入 `cpuCurve` / `gpuCurve`，支持两路联动；仅在自定义档位 `power_mode === 4` 时实时应用，拖动更新有 250 ms 合并。渐变范围为 100–12,700 ms，步长 100 ms；独立输出使用 `toggle_fan_isolated_output`。

| 原生函数 | 确认行为 |
| --- | --- |
| `0x140342C80` | 写 `0x787`；禁用值 `0x81`，启用值为 `0x80 OR floor(clamp(ms, 100, 12700) / 100)` |
| `0x140345AA0` | 读取 `0x7C5`，保留低七位，将 bit 7 设置为独立输出开关，再写回 |
| `0x140342E50` | 准备表写入时向 `0x7C6` 写 `4` 后写 `0`；另一分支写 `0` 释放 |
| `0x1403C2BA0` | 准备 `0x741` 控制位，构建 `0xF00–0xF5F` 共 96 个写入项；批量写后调用锁存提交；另有条件分支更新 `0x767` |
| `0x140345EC0` | 向 `0x7C6` 写 `4`，日志将其称为表锁存提交 |

六组 16 字节表与官方元数据中的 CPU/GPU 升温阈值、降温阈值和占空值表地址一致：`F00 / F10 / F20 / F30 / F40 / F50`。写入函数将 `F20`、`F50` 的首项固定为 0；尾部 `F5D/F5E` 使用输入结构最后一个字节，`F5F` 为该字节与 160 的较大者。尾部控制的完整物理含义仍需核对。

这是原版的原生写入流程证据，不能直接照搬：

- 机型表内占空值有 110、160、180 等数值，不能将它们直接解释为百分比或简单截断到 100。
- 升温/降温表是分开的，普通 UI 温度—百分比点不能直接写进去；点数、迟滞与编码转换仍需追踪。
- `0x7C5` 同时包含背光选择器。当前键盘实现已保留其 bit 7，风扇实现也必须保留其低位，避免互相覆盖。
- 批量写函数逐项发 EC IOCTL；不是固件原子事务。表写入函数没有提供我们需要的逐项读回证明，不能照抄“提交后就视为成功”的行为。
- 需确认退出自定义档位、切换强冷、重启或睡眠后如何恢复原厂表；本机此前读到表为零，不能由原版存在这条路径推断它在本机必定可用。

## GPU：功耗合同和频率偏移分离

前端通过 `get_gpu_tuning_capabilities` 查询能力，自定义调校通过 `apply_live_custom_tweak` 提交。原生能力查询入口为 `0x14033C820`，功耗写入口为 `0x140344AA0`：

- 不支持 DB/cTGP 的能力分支跳过相关 EC 写入。
- 日志标为 Full-Power 的分支只更新 `0x746` 的 DB 值。
- 另一分支构建 `0x743 / 0x744 / 0x746` 的写入列表，分别涉及控制字节、功耗偏移与 DB 值，并按能力返回的范围收敛参数。
- `0x1403453D0` 的“功耗合同恢复”另写 `0x745=0xFF`，并可能调整 `0x751 bit 4`；它涉及机身档位，不能当成无副作用的读回操作。

前端打开自定义面板时，在自定义档位下会调用 `heal_gpu_power_contract`。我们不应复制这种页面读取顺带改硬件的做法；应将恢复放到明确的应用或恢复操作中。

NVAPI 初始化 `0x14018B350` 动态加载 `nvapi64.dll`、查找 `nvapi_QueryInterface`，可见 `0x34C0B13D / 0xE3640A56` 等查询 ID。频率写函数 `0x140341F70` 分别构造 `0x21CF8 / 0x11C94` 版本字段，将 MHz 偏移乘以 1000 后发出间接调用。这证明频率调校走 NVIDIA 驱动接口，而不是把 MHz 写到 EC 功耗地址；本轮没有验证结构的全部字段、查询 ID 的官方命名或驱动兼容范围。

## 背光与续航：更适合近期落地

`set_lighting_sleep_timer` 传入分钟数。原生工作函数 `0x1400EDAE0` 使用 `GetLastInputInfo` 与 `GetTickCount`，将分钟乘以 60,000，与最后输入间隔比较，并切换内部睡眠标记及调用灯光应用函数。不是只有界面按钮。多控制器的关闭与恢复分支尚未全部还原；机耀处可先基于已经验证的 EC 单色通道实现。

`set_auto_min_refresh_on_battery` 在前端有实际调用，说明文字限定自动降低内置屏幕刷新率。当前机耀处同名 API 会保存偏好并立即应用最低档，但 `PowerPolicy` 只处理性能档位，没有把这个偏好接到供电事件。这是现有基础能力可以直接补全的产品差距；原版自动恢复的精确规则尚未恢复。

还观察到离电键盘回退的配置与后端命令字符串，但本轮提取的 JS 没有 `m("set_auto_fallback_kb_on_battery", ...)` 调用。机耀处该兼容 API 目前只记录日志并返回成功，不能把它列为已经实现的省电行为。

## 机型资料：借鉴能力建模，保留本机真值

29 项机型表包含 `project_id`、`bios_project_id`、键盘类型、风扇表、是否支持独立风扇、水冷以及功耗资料。原生还出现 `matched_profile / is_trusted / confidence_reason` 等字段与芯片推断回退日志，适合借鉴“实际硬件信息、匹配依据、用户配置分离”的模型设计。

但同为项目 `0x1A` 不代表同一模具：例如 `X6AR55` 条目的默认 PL 是 75/85/145，带有水冷能力标记，而本仓库已有本机固件默认值与实测记录。不能把这项表当作耀世 15 Air 的权威配置。建议以板号、BIOS 项目号、EC 项目号及实际支持位联合匹配；未匹配设备显示未知，并保留用户编辑的预设与固件读回的区别。

## 其他可借鉴的产品能力

- 命名配置支持创建、复制基础配置、重命名、删除、导入导出；可作为“安静办公/游戏/续航”的统一入口。
- 显示颜色配置有每屏预设与 HDR 提示。机耀处当前 Gamma API 不等于这套完整流程，需补配置应用、恢复和屏幕身份管理。
- 睡眠管理提供断网、Away Mode、系统请求、唤醒计时器、深睡眠和 30 分钟后休眠等选项；这些是界面与调用证据，本轮不认可其宣传文字为实际效果证明。
- Fn 锁、关机 USB、AC Recovery 与 BIOS 高级菜单均有入口。BIOS 高级菜单不能沿用旧文档对 `0x74E bit 4` 的猜测；该位已被本机 Fn 锁采集确认，BIOS 功能需要另外追踪固件变量。
- 灯光页有四区、Logo、灯带、转轴、硬件/软件效果及脚本入口。HID 导入和入口存在不能证明这些灯效适用于当前 EC RGB 键盘。
- 外置水冷页包含 BLE 直连、温控曲线、水泵阈值、LED 与注水排气；原生状态结构包含流量、泵速和保护触发等字段。尚未完成 GATT 特征、命令载荷和断连行为恢复。
- 插件、皮肤、小组件有产品入口。当前隐藏窗口不采样的要求应继续保留；不能照搬额外常驻轮询与动态脚本执行机制。
